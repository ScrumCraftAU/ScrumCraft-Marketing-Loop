# GA4 → Marketing Loop Zap

One Zap, run daily, that loops over our GA4 properties and posts each property's
raw report to the app. The Zap does no mapping: metric definitions (course pages,
checkout pages, conversion events) live in `src/lib/ingest/ga4.ts`.

Each run re-sends the last **42 days**. Upserts make this idempotent, the first run
backfills the dashboard's 5-week baseline, and GA4's late data corrections get picked up.

## Before you start

In Vercel → `scrumcraft-marketing-loop` → **Settings → Deployment Protection →
Protection Bypass for Automation**, create a secret. Zapier sends it as a header so
it can get past SSO. You'll also need the `INGEST_SECRET` value.

### 3. Google Analytics 4: API Request (Beta)
- Account: jason@scrumcraft.com
- HTTP Method: **POST**
- URL: `https://analyticsdata.googleapis.com/v1beta/properties/{{2. property_id}}:batchRunReports`
- Body:
  ```json
  {"requests":[{"dateRanges":[{"startDate":"42daysAgo","endDate":"yesterday"}],"dimensions":[{"name":"date"}],"metrics":[{"name":"sessions"},{"name":"newUsers"},{"name":"engagementRate"}],"limit":10000},{"dateRanges":[{"startDate":"42daysAgo","endDate":"yesterday"}],"dimensions":[{"name":"date"},{"name":"sessionDefaultChannelGroup"}],"metrics":[{"name":"sessions"}],"limit":10000},{"dateRanges":[{"startDate":"42daysAgo","endDate":"yesterday"}],"dimensions":[{"name":"date"},{"name":"pagePath"}],"metrics":[{"name":"screenPageViews"}],"limit":100000},{"dateRanges":[{"startDate":"42daysAgo","endDate":"yesterday"}],"dimensions":[{"name":"date"},{"name":"eventName"}],"metrics":[{"name":"eventCount"}],"limit":10000}]}
  ```
  (Generated by `batchRequestBody()` in `src/lib/ingest/ga4.ts`. If you change one, change the other.)
- Stop on error: **Yes**

### 4. Webhooks by Zapier: Custom Request
- Method: **POST**
- URL: `https://scrumcraft-marketing-loop.vercel.app/api/ingest/ga4?property={{2. property_id}}`
- Data: insert step 3's **Response Body** chip (under `response`). Nothing else. Note: editor test samples may show only "Full Response Data" (a file link) — the app accepts either, but live runs deliver **Response Body**.
- Headers:
  | Key | Value |
  |---|---|
  | `Content-Type` | `application/json` |
  | `x-ingest-secret` | *INGEST_SECRET* |
  | `x-vercel-protection-bypass` | *Protection Bypass for Automation secret* |

A good response is `{"stored": <n>, "warnings": []}`. Errors show up on the Metrics &
sources page (source "last error") and in `raw_events.error`.

### 5–7. Search Console branch (main site only)

Search Console is linked to 552676870 (GA4 → Admin → Search Console links), so the GA4 API returns
`organicGoogleSearch*` metrics for that property. Properties without a link reject them, which would
fail their whole batch, hence a separate branch.

- **5. Filter by Zapier:** only continue if `2. Property Id` (Text) exactly matches `552676870`.
- **6. Google Analytics 4: API Request (Beta):** a copy of step 3 with **Stop on error: No** and this body
  (generated by `searchConsoleRequestBody()` in `src/lib/ingest/ga4.ts`):
  ```json
  {"requests":[{"dateRanges":[{"startDate":"42daysAgo","endDate":"yesterday"}],"dimensions":[{"name":"date"},{"name":"landingPage"}],"metrics":[{"name":"organicGoogleSearchClicks"},{"name":"organicGoogleSearchImpressions"},{"name":"organicGoogleSearchAveragePosition"}],"limit":100000}]}
  ```
- **7. Webhooks by Zapier: Custom Request:** a copy of step 4, with Data = step **6**'s Response Body.

Search Console data reaches GA4 about 48 hours after Google collects it.

## Notes
- The main-site property 552676870 reports in **Adelaide time** (checked 13 Oct 2026). The retired
  legacy property 317178274 ran on Los Angeles time, so its "days" ended at 5:30pm Adelaide.
- The main site is tagged by Site Kit's Google tag **GT-WF6488B**, which sends one `page_view` per
  load to the main stream G-CJDDMN02SK (checked 13 Oct 2026). A leftover `gtag('config',
  'G-N3SL34FSQ2')` snippet for the retired 317178274 is still in the page but sends nothing (SCM-191).
- The property's only configured key event is `reduced_bounce_rate`, so the app uses
  `form_submit` events and checkout page views as conversion signals instead.
